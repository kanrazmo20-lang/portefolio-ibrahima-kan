Application Personnel

Projet de BTS SIO SLAM | Java | 2026-2027

Application de gestion des employés des ligues de la Maison des Ligues de Lorraine (M2L). À l'origine, elle fonctionnait uniquement en ligne de commande, avec un seul utilisateur. Le projet consiste à la rendre multi-utilisateurs grâce à une base de données et à ajouter trois niveaux d'habilitation, sans changer son architecture en 3 tiers.

Ressources fournies

  • Le code source de l'application, un projet Java configuré pour Eclipse
  • La documentation du code (Javadoc)
  • Une bibliothèque pour créer des menus et dialoguer avec l'utilisateur en ligne de commande

Travail demandé

  • Stocker les données dans une base de données pour que plusieurs utilisateurs puissent les partager
  • Mettre en place trois niveaux d'habilitation (voir le tableau ci-dessous)
  • Conserver l'architecture 3-tiers de l'application : présentation (les menus), métier (les ligues et les employés) et données (l'accès à la base)
UtilisateurDroits

Administrateur de ligueGère les employés de sa ligue

Ce que j'ai réalisé

Itération 1

  • Création du MCD de la base de données : 3 entités (ligue, employé, utilisateur) et 2 associations
  • Dépôt du MCD sur le GitHub du groupe, avec une pull request (fusionnée)

Itération 2

  • Écriture du script SQL de création des tables

Technologies utilisées

  • Java
  • Eclipse
  • SQL
  • Git et GitHub

Modèle conceptuel de données

Le MCD contient trois entités : LIGUE (id_ligue, nom), EMPLOYE (id_employe, prenom, nom, email) et UTILISATEUR (id_utilisateur, identifiant, role, mot_de_passe).

  • Association APPARTENIR : un employé appartient à une seule ligue (1,1) et une ligue peut avoir de 0 à n employés (0,n).
  • Association POSSÉDER : un employé a au plus un compte utilisateur (0,1) et un compte est lié à au plus un employé (0,1).

Le champ role de l'utilisateur sert à distinguer les niveaux d'habilitation : employé, administrateur de ligue et super-administrateur.
